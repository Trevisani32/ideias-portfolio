### Etapa — Dividir o projeto em partes

**Objetivo:** quebrar o projeto em partes pequenas, que dá para construir, entender e testar uma de cada vez.

#### Por que dividir

Pedir o projeto inteiro de uma vez gera uma resposta enorme, difícil de acompanhar, com muita coisa acontecendo ao mesmo tempo. Com partes pequenas, você entende cada pedaço, vê funcionando no navegador e só depois segue em frente. É assim que se trabalha em equipes de verdade.

Uma boa parte:

- entrega algo que dá para **ver funcionando** no navegador;
- mexe em poucos arquivos;
- cabe numa resposta da IA sem ficar gigante.

#### O ciclo de cada parte

Todas as partes seguem o mesmo ciclo:

1. **Peça:** envie o prompt da parte para a professora.
2. **Leia:** leia a explicação inteira antes de copiar o código.
3. **Cole e salve:** coloque o código nos arquivos indicados.
4. **Teste:** abra com o Live Server (clique com o botão direito no `index.html` → **Open with Live Server**) e confira o que a parte diz que deve acontecer.
5. **Pergunte:** use as perguntas sugeridas e as suas próprias até tudo fazer sentido.
6. **Salve no Git:** faça um commit com a mensagem sugerida e envie para o GitHub.

#### Confira a divisão com a professora

As partes deste projeto estão sugeridas logo abaixo. Antes de começar, peça para a professora explicar a ordem:

```prompt
Pensei em construir o projeto "{{titulo}}" nestas partes, nesta ordem:

[COLE AQUI A LISTA DE PARTES DESTA PÁGINA]

Me explique por que essa ordem faz sentido, o que cada parte entrega e o que eu vou aprender em cada uma. Se você mudaria alguma coisa, explique por quê. Ainda não escreva código.
```

Anote as partes no final do `docs/projeto.md`, numa seção "Plano de construção". Assim você acompanha o que já foi feito.
